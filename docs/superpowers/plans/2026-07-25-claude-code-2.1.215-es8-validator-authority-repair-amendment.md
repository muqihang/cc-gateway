## 3. Holistic Architecture Analysis

At frozen `7972307`, `backend/internal/oracleevidence/validator.go` is used only by the dedicated
tests. No product caller is involved. The relevant call path is:

```text
TestEvidenceMutations
  -> ExecuteMutationCorpus
    -> decodeMutation
    -> executeMutation
      -> applyJSONMutation / synthetic subject helper
      -> subject-specific check or DecideAdmission
    -> MutationResult{Decision: "deny"}

TestEvidenceAdmission
  -> DecideAdmission
    -> DeriveCoverage
    -> caller RequiredArtifacts + caller Artifacts + caller ExternalBindings
    -> containsSensitiveEvidence
```

The observed defects are structural, not test-count or naming problems:

1. `executeMutation` returns only a code. If a subject validator allows the mutated value, control
   falls through to `mutation_recipe_invalid`; if it denies, `ExecuteMutationCorpus` still writes
   `Decision: "deny"` unconditionally. A renamed ID test cannot detect that hard-coded result.
2. `source_file` creates `{kind:"regular"}` in memory, replaces that string with `"symlink"`, and
   denies. It opens no source, applies no generic source replacement, and proves no path, bytes,
   digest, file type, or bound.
3. `DeriveCoverage` validates only rows supplied by the caller. A caller may omit an authoritative C,
   E, or D row, omit a contradiction, or set an authoritative row disabled and still reach allow.
4. `DecideAdmission` treats caller `RequiredArtifacts` as authority. Removing one artifact from the
   required set, artifact list, and external bindings produces a smaller internally consistent allow.
5. The value/key regex covers credential-like values and only part of `raw_material_key`; it does
   not independently enforce the frozen leak-report families `absolute_path`, `symlink`,
   `mode_mismatch`, or `size_overflow`.
6. `parsePointerIndex` accumulates directly into `int`. On 64-bit,
   `18446744073709551616` wraps to `0`, then may pass a small-array bounds check. Bounds are checked
   after the unsafe conversion has already happened.

The schema-keyword shape defect from the initial review is closed at `7972307` and is outside this
repair. `schema.go` may change only for the minimal source-root/authority attachment described below;
the Draft 2020-12 keyword implementation must not be redesigned.

## 8. Overflow-Safe JSON Pointer Semantics

`parseBoundedDecimalIndex` applies this order before any machine-int conversion:

1. Reject empty input, `+`, `-`, any nondigit, and leading zero when length is greater than one.
2. Accumulate in `uint64` only after checking
   `value > (4096 - digit) / 10`; reject instead of wrapping.
3. Reject a parsed value greater than `4096`.
4. In `parsePointerIndex`, compare the `uint64` value with `uint64(length)` without computing
   `length+1`: normal access requires `index < length`; `allowEnd` requires `index <= length`.
5. Convert to `int` only after the fixed `4096` cap and slice-length check both pass.

All parse/canonical/overflow/out-of-bounds failures are wrapped as
`mutation_recipe_invalid` at the mutation boundary. The parser never reports a wrapped numeric value
in diagnostics. The limit `4096` equals the maximum `maxItems` in the frozen 50-file bundle;
schema-bundle drift requires a new reviewed authority rather than silently increasing it.
